# MARBLE_CRYSTAL_LENS_V248 — نوار پایین: یک عدسیِ کریستالی روی یک تصویرِ دو-پاسِ واقعی

> تاریخ: 2026-10-30 · برنچ: `arena/8ac95133-marbleng`
>
> **خواسته:** نسخهٔ قبلی رد شد: یک دیسک شیریِ مات، تایپوگرافیِ رستر و تار، فشردگیِ عمودی، و هیچ
> خاصیت نوریِ واقعی. این فصل ثبت می‌کند که چه چیزی دور انداخته شد، چه چیزی از صفر ساخته شد، و
> چرا این بار شیشه «شیشه» است.
>
> **نتیجه:** `LiquidGlassBottomBar` با امضای `items: List<NavigationTabItem>` /
> `selectedIndex` / `onTabSelected` / `modifier` بازنویسی شد. ریاضات در `LiquidGlassLensSpec`
> است و روی JVM تست می‌شود. هیچ `Modifier.blur`، هیچ `RenderEffect`، هیچ `RuntimeShader` و هیچ
> `ImageBitmap` در مسیر رسم نیست.

## ۱. هندسه و تناسب

| جزء | مقدار | چرا |
|---|---|---|
| ارتفاع کپسول | `68.dp` (یا `72.dp` در حالت Large) | دو ارتفاعی که بریف مجاز دانست |
| قطر عدسی | `52.dp` | دقیقاً عدد بریف |
| هوای بالا/پایین | `۸.dp` در ۶۸ و `۱۰.dp` در ۷۲ | `breathingRoomDp` این را روی JVM تضمین می‌کند |
| شکل | `CircleShape` | استادیوم کامل |
| آیکن غیرفعال | `22.dp` در `#5F6368` | عدد بریف |
| برچسب غیرفعال | `11.sp`، `Medium`، `#5F6368` | عدد بریف |
| برچسب فعال | `Bold`، رنگ اکسنت یا `#1E5E3A` | «سبز/فیروزه‌ای پویا» |
| بزرگ‌نمایی | `1.30×` برای هم آیکن و هم متن | داخل باند ۱٫۲۸–۱٫۳۲ |

ارتفاع ۶۸ با عدسی ۵۲ یعنی **۱۶dp اختلاف**، یعنی ۸dp هوا از بالا و ۸dp از پایین. نسخهٔ V247 با
کپسول ۶۰dp، آیکن ۲۳dp، برچسب و فقط ۴dp پدینگ عمودی ساخته می‌شد؛ همان چیزی که «فشردگیِ عمودی»
نامیده شد. لایهٔ ردیف حالا `22 + 3 + ~13` را در ۶۸dp وسط‌چین می‌کند و ۱۵dp هوا در هر طرف دارد.

## ۲. خط لولهٔ دو-پاس

این بار دو پاس داریم، اما **نه** به شکلی که V247 داشت:

| پاس | چه می‌کشد | چگونه محدود می‌شود |
|---|---|---|
| پایه | همهٔ تب‌ها در مقیاس ۱٫۰، آیکن ۲۲dp، متن ۱۱sp Medium، `#5F6368` | با یک مسیر **EvenOdd** از داخل بیضی عدسی **بیرون** نگه داشته می‌شود |
| تصویر | همان ردیف با همان لنگرها، ۱٫۳۰×، Bold، رنگ اکسنت | فقط **داخل** بیضی عدسی کلیپ می‌شود |

نکتهٔ اصلی همان «بیرون نگه داشتن» است. در V247 لایهٔ پایه زیر لایهٔ بزرگ‌شده باقی می‌ماند؛ چشم
دو نسخه از یک واژه را در دو مقیاس روی هم می‌دید و آن را «شیری/تار» تفسیر می‌کرد. عدسی واقعی
تصویر دوم را روی تصویر اول نمی‌کشد؛ **جایش می‌گذارد**. پس:

```kotlin
val outsideLens = Path().apply {
    fillType = PathFillType.EvenOdd
    addRect(Rect(0f, 0f, size.width, size.height))
    addOval(Rect(cx - rx, cy - ry, cx + rx, cy + ry))
}
clipPath(outsideLens) { this@drawWithContent.drawContent() }
```

و پاس دوم دقیقاً مکمل آن است:

```kotlin
clipPath(aperture) { this@drawWithContent.drawContent() }
```

هر دو ردیف از یک `Row`، یک `weight(1f)`، یک پدینگ داخلی و یک لنگر استفاده می‌کنند، پس مرز
عدسی فقط **مقیاس** را عوض می‌کند، نه موقعیت را.

## ۳. مادهٔ نوری

| جزء | مقدار |
|---|---|
| کپسول | `Color.White.copy(alpha = 0.88f)` |
| سایهٔ محیطی | `blur = 20.dp`، `offsetY = 6.dp`، `Black @ 0.07` |
| لبهٔ کپسول | `1.dp` با گرادیان عمودی `White @ 0.60 → 0.15` |
| بدنهٔ عدسی | `White @ 0.12` — شفاف، نه مات |
| رینگ دوگانه | `1.5.dp`، گرادیان خطی `0.95 / 0.20 / 0.50` |
| کاستیک | گرادیان شعاعی `Transparent → White @ 0.25` روی محیط داخلی |
| سایهٔ قطره | `8.dp`، `offsetY = 3.dp`، `Black @ 0.14` |
| بازتاب موضعی | یک هات‌اسپات کوچک در ربع بالا-چپ + کمان ۲۰۰°–۳۴۰° |

سایهٔ محیطی یک لایهٔ مستقل است: یک `Box` هم‌اندازه که `6.dp` پایین‌تر نشسته و
`Modifier.shadow` روی `CircleShape` دارد. چون Compose سایه را حول شکل می‌اندازد، جدا کردن لایه
تنها راهِ داشتن offset واقعی است.

## ۴. سینماتیک و فیزیک

| لحظه | چه اتفاقی می‌افتد |
|---|---|
| `down` | عدسی در همان فریم زیر انگشت می‌نشیند (`heldLensPx`) و یک `TextHandleMove` می‌زند |
| `drag` | هر جابه‌جایی `clamped(current + dragAmount)` را می‌نویسد؛ `VelocityTracker` سرعت را می‌دهد |
| کشیدگی | `scaleX = 1 + min(|v| / 3000, 0.25)` و `scaleY = 1 − min(|v| / 6000, 0.12)` |
| `up` | نزدیک‌ترین تب publish می‌شود، یک `TextHandleMove` می‌زند، و فنر عدسی را به لنگر می‌برد |
| فنر | `spring(dampingRatio = 0.65f, stiffness = Spring.StiffnessMediumLow)` |

### کران اجباری

```kotlin
val minX = paddingStartPx + lensWidthPx / 2f
val maxX = containerWidthPx - paddingEndPx - lensWidthPx / 2f
return x.coerceIn(minX, maxX)
```

این فرمول در `LiquidGlassLensSpec.clampLensCenterX` است و در `onDragStart`، هر فریم درگ،
`onDragEnd`، `onDragCancel` و مسیر انتخاب بیرونی اعمال می‌شود. اگر عرض کپسول از خود عدسی هم
کمتر شود، هر دو کران برعکس می‌شوند و مرکز برنده است (تست
`aCapsuleNarrowerThanTheLensCollapsesToTheMiddle`).

### راست‌به‌چپ

مختصات عدسی همیشه پیکسل فیزیکی از چپ است. فقط نگاشت پیکسل↔تب آینه می‌شود
(`tabCenterX(..., rtl = true)` و `indexAt(..., rtl = true)`).

### ۱۲۰ فریم

`lensX` (یک `Animatable`)، `heldLensPx` و `velocityX` فقط داخل `graphicsLayer`، `Canvas` و
`drawWithContent` خوانده می‌شوند. درگ، فاز Draw را باطل می‌کند، نه composition را؛ ردیف تب‌ها
یک بار به‌ازای انتخاب ساخته می‌شود، نه یک بار به‌ازای فریم.

## ۷. آنچه عمداً انجام نشد

1. **`RuntimeShader` / AGSL.** یک شیدر که روی دستگاهی کامپایل نشود **هیچ چیز** رسم نمی‌کند؛ برای
   نوار پایین یعنی از دست رفتن کل ناوبری. بزرگ‌نمایی این بار یک مقیاس وکتوری ۱٫۳۰ است، نه یک
   شیدر.
2. **بلور پس‌زمینه.** بریف برای شیشه فقط سفید ۰٫۸۸ خواست. سامپل کردن صفحه و بلور کردنش همان
   مسیری بود که متن را تار می‌کرد؛ حذف شد.
3. **بزرگ‌نمایی فقط آیکن انتخاب‌شده.** پاس تصویر کل ردیف را در حالت فعال و بزرگ رسم می‌کند و
   عدسی فقط پنجرهٔ آن است؛ دقیقاً همان چیزی که «ذره‌بین» را از «افکت آیکن» جدا می‌کند.
4. **دو مجموعه کنترل.** لایهٔ تصویر `clearAndSetSemantics { }` دارد و شمارنده/چراغ اتصال فقط روی
   لایهٔ پایه رسم می‌شوند. برای screen reader نوار همان چهار تب است.
